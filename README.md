# 斗兽棋 · 森林翻牌对战

手机竖屏优先的 4×4 翻牌斗兽棋 H5。使用固定斜俯视的 2.5D 棋盘与黏土动物素材，提供五档公平电脑对手、翻牌与吃子动画、规则说明、音效、每局三次悔棋和胜负结算。

## 启动与构建

开发环境需要 Node.js 20.19+ 或 22.12+，推荐使用 Node.js 22。当前已安装依赖，可直接启动：

```bash
npm run dev
```

打开终端输出的本地地址，默认是 `http://127.0.0.1:5173/`。重新安装依赖使用 `npm ci`；首次安装开发依赖需要网络，游戏运行不需要外部网络。

```bash
npm run check       # TypeScript 静态检查
npm test            # 规则、状态、AI 与取消边界测试
npm run build       # 检查类型并生成 dist/
npm run preview     # 预览生产构建，默认端口 4173
```

`dist/` 已包含完整静态产物，约 0.96 MB（未启用 HTTP 压缩的文件总大小）。部署时上传该目录的全部内容即可；支持域名根目录或 `/forest/` 等子目录，无需后端服务或 URL 重写。

也可以完全断网，通过本机已有的 Python 启动静态产物：

```bash
python3 -m http.server 8080 --bind 127.0.0.1 --directory dist
```

浏览器打开 `http://127.0.0.1:8080/`。不要直接双击 `index.html`，应用使用浏览器模块和 Worker，需要通过 HTTP 服务加载。

手机在同一局域网内预览开发版时，可使用 `npm run dev -- --host 0.0.0.0`，然后访问终端显示的 Network 地址。

## 离线与保存范围

- 所有图片、脚本、样式与音效都在本地，不使用 CDN、在线 AI、账号或服务接口。
- 初次通过网站访问需要加载网页；加载完成后可断网继续玩，包括首次电脑思考、悔棋、重开及返回大厅。
- 生产版本的 AI Worker 内联在脚本中，重新创建 Worker 无需额外下载。音效由 Web Audio 合成。
- 仅使用 `localStorage` 保存难度和音效偏好。刷新、关闭或退出不会保存棋局。
- 不提供 Service Worker / PWA 离线缓存；断网后关闭网页，再通过远程网址重新打开不在本版范围内。本地静态服务器不受这一限制。

## 规则

1. 红蓝双方各有象、狮、虎、豹、狼、狗、猫、鼠各一枚，16 枚全部随机盖在棋盘上。
2. 玩家先翻，第一枚颜色决定玩家阵营。每回合翻开一枚暗棋，或移动己方一枚明棋，行动后换对方。
3. 明棋只能沿上下左右移动一格。不能斜走、跳跃、进入己方棋子所在格或直接攻击暗棋。
4. 大小顺序为 **象＞狮＞虎＞豹＞狼＞狗＞猫＞鼠**。双方都能攻击相邻的敌方明棋：大吃小；小攻大时进攻者被吃，守方留在原格。鼠攻象获胜，象攻鼠则象被吃。攻击失败也消耗一回合。
5. **同级相撞双方同时消失。最后两枚同级相撞导致双方全灭时，主动进攻方获胜。**
6. 一方棋子全部被消灭即失败；未翻开的棋子仍算存活。被强敌堵住时仍可主动攻击，不会提前判负；最后一枚棋子攻击失败则立即失败。
7. 相同棋盘和相同行棋方累计出现三次，判平局。
8. 连续 **20 步**没有翻牌或交战时，依次结算：场上还有任何暗棋则平局；全部翻开后，若一方仅剩一只象、另一方有鼠，则有鼠的一方获胜（鼠方可以有多个棋子，包括象）；其余情况按固定等级比较双方最大棋子，较大者获胜，相同则平局，不比较数量或第二大的棋子。象方还有其他棋子时不触发鼠象例外。
9. 双方每行动一次算一步；翻牌、成功吃子、失败攻击或同级双消都会重置静步计数。每步依次判断最后同级双消、全灭、无合法行动、三次重复、20 步结算；重复局面与 20 步同时触发时仍优先判重复平局。

每局最多 **3 次悔棋**。一次撤销玩家上一步及电脑随后的一步；电脑思考中可立即撤销。翻牌可撤销但不重新洗牌，首翻撤销后阵营重置，结算后不能悔棋。重复局面记录和静步计数会一起恢复，已消耗的悔棋次数不会恢复。

## 操作

- 点击暗棋翻牌；点击己方明棋选中，再点击目标格移动或攻击。
- 绿框表示可以移动，橙框表示可以攻击。
- 规则与确认弹窗打开时暂停对局推进；切到后台也会停止电脑请求，回来后恢复。
- 对局设置中可以重新开局；退出或重开进行中的棋局需要确认。
- 音效默认开启，在首次操作后启用，可以随时关闭；没有持续背景音乐。
- 电脑端也支持鼠标；棋盘聚焦后可用方向键选格、Enter 或空格操作。浏览器支持时，`F` 切换全屏、`Esc` 退出全屏。横屏全屏采用棋盘与操作区左右排列；更窄或更矮的全屏视口可以在页面内部滚动到全部控件。

## 五档电脑

| 难度 | 决策 | 搜索预算 |
| --- | --- | --- |
| 入门 | 全局评价、直接胜机；在评分相近的走法中随机选择 | 上限约 120 毫秒，通常提前返回 |
| 简单 | 加查反吃交换；明棋搜索至 2 步，保留小幅随机性 | 上限约 200 毫秒，通常提前返回 |
| 普通 | 暗棋概率采样树搜索；明棋迭代搜索至 4 步 | 约 500 毫秒 |
| 困难 | 增加采样与战术计算；明棋迭代搜索至 8 步 | 约 2 秒 |
| 专家 | 增加采样与远期探索；明棋迭代搜索至 14 步 | 约 5 秒 |

五档共用全局评价，考虑随剩余动物变化的子力价值、鼠象克制、安全退路、交换与反吃、协防、可达追击路线和围堵。领先时争取翻牌或吃子推进，劣势时可以选择规则允许的平局。入门与简单也会判断明显危险，通过减少前瞻和放宽相近走法的选择来降低强度。

电脑与玩家同样可以发起失败攻击。搜索按实际损失己方棋子评估这类行动，不把“可以攻击”误当成“能吃掉对方”；存在安全走法时会考虑保住棋子，仅剩失败攻击时也能正常行动和结算。

AI 只接收公开棋盘和按固定顺序排列的未公开棋子集合，不接收暗棋真实位置。每个根部翻牌候选先按完整剩余集合评估风险；后续使用分层概率采样，一轮覆盖每种可能身份再重新随机排序。搜索中双方后续决策只能使用当时已经公开的信息，不预知下一枚暗棋。

暗棋阶段采用带战术先验的对抗采样搜索，每个完成的模拟立即积累到候选统计。普通、困难、专家的采样路径上限分别为 6、10、16 步，这不等于穷尽所有分支的搜索深度。全部翻开后改用 Alpha-Beta 剪枝、走法排序、历史感知的局面缓存和连续吃子延伸，避免只看刚吃到一枚棋子的短期收益。

明棋搜索在预算到达时返回上一轮完整迭代的行动；暗棋搜索返回已完成模拟支持的候选。预算覆盖初始候选评分，极短预算下也保留合法行动；直接获胜时提前返回。时间、树节点数和缓存容量均有限制。因此深度是上限，强度也受设备性能和翻牌运气影响。Worker 启动、垃圾回收与浏览器调度存在额外开销，没有人类棋力评级或跨设备胜率保证。

电脑计算异常会明确提示重试，不会静默切换难度。旧请求在悔棋、重开、退出和暂停后失效，返回行动仍需经过规则引擎复核。

## 工程与素材

| 路径 | 职责 |
| --- | --- |
| `src/game/` | 类型、规则引擎、公开信息转换、悔棋会话 |
| `src/ai/` | 全局评价、概率与残局搜索、Worker、请求取消 |
| `src/ui/` | 图片预加载、Canvas 绘制与命中、Web Audio |
| `src/main.ts` | 大厅、对局与弹窗流程 |
| `src/style.css`、`src/tokens.css` | 响应式布局与视觉样式 |
| `tests/game.test.ts` | 规则、AI、公平性和会话测试 |
| `tests/ai-strategy.test.ts` | 固定战术、独立残局裁判、搜索预算与历史隔离 |
| `tests/baselines/ai-v1.ts` | 冻结的升级前 AI，仅用于对照，不进入生产包 |
| `scripts/benchmark-ai.ts` | 固定洗牌、固定首翻、成对换边的新旧 AI 对战 |
| `assets/source/` | 从原始目录复制出的素材 |
| `assets/manifest.json` | 输出资源与源图片、裁切区域的对应关系 |
| `public/assets/` | 运行时使用的 38 个 WebP 资源 |
| `scripts/prepare-assets.mjs` | 素材复制、裁切、透明边缘处理与压缩 |

图片来源为用户提供的 `ImageMaterials/`。大厅、对局、结算分别参考 `-9`、`-12`、`-10`；原始文件和 `.idea` 未改动。程序先复制，再处理副本，运行时不访问 `ImageMaterials/`。需要重新生成资源时运行 `npm run assets`，之后重新构建。

棋盘底图现使用 `无格薄荷绿木框棋盘.png` 的复制件，输出为 `public/assets/board.webp`。从原 `薄荷森林四乘四棋盘-2.png` 的副本提取单个棋格，生成 `cell-slot.webp`，保留原有奶油色凹槽、绿色边沿、纹理与阴影，再独立排成 4×4。暗棋继续使用带叶芽标志的立体木质牌背，空位保留原材质凹槽。格子、棋子、选中框、空位提示与点击坐标共用落点，避免与底图预绘格子错位。

棋子尺寸以凹槽内面为准：牌背整体等比放入内面，动物保留立体高度、底座收进格内并留出边距。跨行移动同时插值位置和尺寸，落地后保持一致的透视比例；点击区域也随实际绘制尺寸更新。

`window.render_game_to_text()` 提供公开局面供自动化验证，不包含暗棋身份；`window.advanceTime(ms)` 可以推进棋盘动画。固定测试场景接口只存在于开发模式，生产包不包含 `__loadTestFixture`。

## 验证记录

原版交互与设备覆盖详见 [验收记录](docs/verification.md)，本次算法升级的测试、对战数据与限制详见 [AI 升级记录](docs/ai-upgrade.md)。真实 iOS / Android 设备、微信内置浏览器、Safari / Firefox 的实际运行与音效听感尚未验收。

可复跑新旧对照，例如：

```bash
# 同档、每步同时间上限；每个种子交换双方各下一局
npm run benchmark:ai -- --pairs=12 --seed=1101 --difficulty=hard --time=150 --out=ai-benchmark.json
# 使用各版本普通档的实际默认预算
npm run benchmark:ai -- --pairs=6 --seed=2101 --difficulty=normal --out=ai-default.json
```

报告包含胜、负、平、截断局、耗时和每步行动。得分率按 `(胜局 + 平局 / 2) / 正常完成局数` 计算；超过 240 步的截断局单列，不伪装成平局。固定种子可重建洗牌、首翻和随机源，但墙钟预算受机器负载影响，不保证每次行动完全相同；自动化公平性测试使用固定节点预算验证确定性。
