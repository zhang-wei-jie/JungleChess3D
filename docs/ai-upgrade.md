# AI 能力升级与验证

日期：2026-11-15。此次修改针对“电脑缺乏全局判断、动作机械”，保留已确认的规则、悔棋方式、离线运行和界面流程。

后续 20 静步规则已更新：有暗棋时平局；全部翻开后先处理“仅剩象遇敌鼠”的例外，再比较最大棋子。真实对局与五档 AI 共用同一结算逻辑，新增回归覆盖按等级/鼠象例外获胜、通过交战避免静步判负，以及有暗棋时求和。最新验证见 [验收记录](verification.md)；本文原有对战统计仍对应升级时的规则，未按新规则重新进行棋力对照。

## 实现

- **动态子力**：按双方尚存动物的克制关系调整价值；鼠在对方象仍存活时更有战略作用，象在敌鼠消失后也会改变判断。
- **安全与交换**：同时观察攻击者、真正能够反吃的协防棋子、安全退路与多重威胁，连续吃子延伸避免只计算眼前收益。
- **机动与追击**：沿可通行的安全空格寻找接近目标的路线，暗棋与己方棋子会阻挡路线；评估限制敌方退路的配合。
- **推进与求和**：评价包含静步计数，搜索沿用真实规则的重复局面记录。存在可证胜利时避免主动三次重复，劣势可以选择合法平局。
- **分阶段搜索**：有暗棋时使用带战术先验的对抗概率采样树；全明棋时使用迭代加深 Alpha-Beta、走法排序和历史感知缓存。两种搜索均调用与实际对局相同的状态转换。
- **分层翻牌采样**：根部候选遍历完整公开剩余集合评估翻牌；后续采样每轮覆盖全部可能身份，顺序随机。每次完成的模拟立即保留，避免额外计算因为整层未完成而全部丢弃。
- **强度分档**：五档共享全局评价，入门和简单在相近评价的候选中保留随机性；普通、困难、专家增加采样与前瞻。没有添加故意送子或固定走子脚本。

入门、简单、普通、困难、专家的搜索预算分别为 **120 / 200 / 500 / 2000 / 5000 毫秒**。低档和直接胜机通常提前返回。暗棋采样路径上限分别为普通 6、困难 10、专家 16 步；明棋迭代深度上限为 1 / 2 / 4 / 8 / 14 步，叶子另查连续吃子。采样路径长度与完整搜索深度属于不同指标，不混用。

预算覆盖初始候选评价，零预算也返回合法行动。单次搜索最多保留 12,000 个采样树节点、12,000 个静态评价缓存项和 8,000 个明棋搜索表项；运行结束或取消后由 Worker 释放。预算是计算目标，浏览器调度和垃圾回收可能带来少量超时。

## 公平性与取消

`GameState` 继续只在规则层保存真实暗棋。Worker 接收的 `Observation` 包括公开棋盘、固定排序的剩余集合和判和历史；暗格只有 `{ kind: 'hidden' }`。每个翻牌结果按当前公开集合产生，之后的选择也只使用该时点已公开的内容。

搜索表的值缓存包含静步与仍可能重复的历史；无关历史仅从缓存键排除，不会修改实际规则记录。只用于走法排序的提示可以跨路径复用，不能直接当作另一段历史的局面得分。

原有请求标识、Worker 终止和主线程合法性复核继续生效。规则弹窗、悔棋、重开、退出和切后台均取消旧请求；关闭弹窗后从当前公开局面重新计算。

## 自动化回归

TypeScript 检查、生产构建以及 **60 项测试全部通过**。其中原有 40 项继续覆盖规则、首翻、平局、悔棋和信息隔离，新增 20 项覆盖：

- 动态鼠象价值、拒绝有反吃保护的诱饵、五档识别最后一只象受鼠攻击的即时危险。
- 沿可达路线追击；两子配合围堵。小残局使用独立的合法走法穷举裁判，确认选中行动仍保有强制胜利，包括一个五步无法结束、七步能够强制获胜的局面。
- 优势临近 20 静步时推进、劣势求和、存在强制胜利时避开第三次重复。
- 评价换边反号、输入不可变、零节点预算、模拟结果持续积累、历史隔离。
- 相同随机源和节点上限的完整候选统计一致；交换真实暗棋位置后，经过多次概率模拟的候选统计仍完全相同。

```bash
npm run check
npm test
npm run build
```

固定战术用例用于防止具体能力回退，不等同于对真人的棋力评级。

## 新旧对照

旧实现冻结在 `tests/baselines/ai-v1.ts`，使用旧评价、旧算法和旧难度参数，仅供测试。双方都只拿到 `observe()` 的公开结果。

每个种子固定洗牌和首翻位置，再交换新旧引擎控制的人类/电脑角色各下一局。每步随机源由种子和步数派生。胜一分、平半分；超过 240 步的截断局另列，不计为平局。以下定版实验均无截断局：

| 对照 | 种子与局数 | 新版胜 / 负 / 平 | 新版得分率 | 实际平均耗时：新 / 旧 |
| --- | --- | --- | --- | --- |
| 困难档，双方每步同为 150 毫秒上限 | 1101–1112，24 局 | 10 / 6 / 8 | 58.3% | 130.2 / 74.3 毫秒 |
| 普通档，各版本实际默认设置 | 2101–2106，12 局 | 8 / 1 / 3 | 79.2% | 350.8 / 6.0 毫秒 |

同时间上限实验控制了每步允许计算的时间，但旧版会提前完成低深度搜索，因此两版实际消耗的时间并不相等。默认普通档的改善同时包含算法变化、深度上限变化与预算从 250 增至 500 毫秒的作用，不能全部归因于某一条评价公式。

这 36 局反映本机、这些种子和该旧版对手上的改善。24 局同上限结果有正向差异，但样本仍小；12 局默认设置结果也不能推出真人对战、所有开局或不同设备上的稳定胜率。

迭代阶段还运行过三个探索批次：16 局 7 胜 4 负 5 平、16 局 6 胜 5 负 5 平、20 局 9 胜 6 负 5 平。这些对应早期采样实现，未混入上表的定版统计。

可复跑命令：

```bash
npm run benchmark:ai -- --pairs=12 --seed=1101 --difficulty=hard --time=150 --out=ai-equal.json
npm run benchmark:ai -- --pairs=6 --seed=2101 --difficulty=normal --out=ai-default.json
```

脚本输出完整行动记录和实际耗时。[定版统计文件](ai-benchmark-results.json) 保留逐局结果、配置和源文件 SHA-256。墙钟预算受 JIT、垃圾回收和负载影响，重跑不保证逐步一致；确定性由固定节点预算测试单独验证。

## 浏览器与设备边界

使用本机 Chrome 157.0.8103.52，Playwright 的 390×844 手机视口与触控模拟，生产构建在本地静态服务器运行。页面载入后切断网络，再验证五档首次 AI 行动、专家计算期间的交互取消，以及完整普通对局。

**25 项浏览器断言通过**：五档首步与公开状态、完整回合及思考中悔棋、首翻阵营复位、旧结果隔离、规则暂停与恢复、重开、退出、结算禁悔棋、再来一局及错误/网络检查。断网普通对局经过玩家 21 次操作、双方共 42 步正常结算，电脑获胜；整个离线阶段没有 HTTP 请求、页面异常或控制台错误。

从点击翻牌到电脑行动完成的实测时间约为 191 / 198 / 698 / 2214 / 5197 毫秒，包含翻牌和电脑行动动画、Worker 启动等开销。专家思考时打开规则弹窗响应约 16 毫秒。取消后等待超过原五秒预算，确认过期结果没有修改棋局。这些是本机单次浏览器测量，不是手机性能承诺。

运行命令如下，预览端口可自行指定；不需要下载额外浏览器，脚本使用已安装的 Google Chrome：

```bash
npm run preview -- --port 4175 --strictPort
node scripts/verify-ai-browser.mjs --url=http://127.0.0.1:4175/ --out=/tmp/jungle-ai-browser
```

还使用 `develop-web-game` 的原始动作客户端验证开发版真实棋盘点击、AI 回应和公开状态输出，仅适配本机 Chrome 的启动路径。已查看棋盘、专家思考、规则暂停和结算截图。

浏览器详细实测数据见 [浏览器报告](ai-browser-results.json)。以上是桌面 Chrome 的模拟视口验证，未做真实 iOS / Android、微信内置浏览器、Safari、Firefox 或手机续航与发热测试。未据此声称真人水平或专家档不可战胜。
